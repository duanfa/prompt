# 提取清单和证据

- 每个目录 ID 恰好交一项。已取值写 `items`，缺失、未知和不适用写 `omissions`。相同原因可合并 ID。使用 schema 定义的状态，写明具体字段、所查位置和缺什么。旧清单里的 Y、N、Rxx 是格式提示，值提交实际内容。能取出的清单项都记录，包含规则暂时未引用的项目。
- 每个提供或列出的材料槽位恰好一条 `materials`。未提供和加载失败沿用运行器状态。“可读”或“部分可读”写实际看到的标题、栏位或画面。定位到真实内容后再确认文种。URL、文件名及无文字层的 PDF 都不能单独说明内容。
- `evidence` 写数据来源、位置和短原文或具体画面。`source` 用 schema 给出的原始键。原件用材料槽位，位置逐字使用 `frames[].location`，网页位置用 `pageText`。申报字段、网关上下文和附件盘点的来源键均用 `request`，位置填写 `request`、`routing` 或 `inventoryStatus` 下的对应路径。核查回执用 `checks` 及其对应字段路径。名称按原件抄录，判断一致时援引两侧原文。
- 申请日和阶段使用请求明确给出的业务字段。缺业务申请日时，成立月数、是否有效、是否快到期、近三月等派生项留空。证照、合同、税费材料的落款日期各归其本栏。
