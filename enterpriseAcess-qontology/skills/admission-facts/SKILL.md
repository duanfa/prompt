# 跨材料核对和属性映射

- 对照本次属性的编码、中文定义、类型及清单事实。每条映射引用已有清单 ID 或本次直接证据，给出推导依据。字段用法与定义冲突、证据不足或枚举无合适取值时登记缺口。确实为待核状态的属性可按定义交 0。风险状态 1 表示确认命中，核查状态 1 表示已核实通过，分别看属性说明。
- 跨材料补齐项须来自此前缺失的条目，引用两边原文。重点核对执照和申报主体、开户户名、法人姓名、租赁主体、印文、补充材料主体以及工商状态。比较名称允许忽略空白、括号全半角，保留形近字、少字、多字及印文简称差异。两边已取值才能比较。原件栏位和工商值不互相覆盖。
- `founded` 对应 B04 确认的成立日期。业务申请日、阶段来自本次请求。`months` 由运行器计算。`legalEntity` 根据本体规定和主体存续、独立用工资格证据核验。
- `licenseMissing`、`idMissing` 表示是否提交。`license`、`idFront`、`idBack` 表示材料核验。`bank` 需要认可的账户性质、实际户名匹配及满足影像要求。`leaseSealGap` 需要看到明确缺章或现场核验，双方都出现印迹时另行检查印文和主体。`siteVideo`、`siteReal` 需要能支持相应核查状态的材料。采样所见只支持可见内容和起点。
- `videoEntry` 为首帧入口或前台取 1，明确为工位区等非入口取 -1。`photos` 只计同时有任务单关联和交付证明的照片。跨主体复用关联需该申请与独立对照申请。`chain` 依据主体相符、可核验的组合证据及本体要求。
- 返回 `mapped`、`unresolved`、`completedItems`。准入结论、人工审核处置、案例预期结果属于运行器或真实外部流程的输出。
