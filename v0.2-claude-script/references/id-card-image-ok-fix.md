# 本体属性映射与业务判断改由模型决定（2026-11-08）

trace 2e42229e9e68b930fb54423d381fbd66 中，材料已记录法人身份证有伪造嫌疑，旧默认映射却只取彩色与鲜章，导致影像合格为 true。

最终实现按用户要求采用提示词约定，撤销先前给身份证增加专用计算分支的实现，并移除其余本体业务属性的默认映射及固定派生。

## 当前职责

- 模型读取当次属性 label/comment、规则条件和清单事实，选择 map / skip，并通过 set 显式提交综合判断、分类或状态；单条依据也可提交 set。
- 提示词要求综合查看支持和反对证据。有明确伪造嫌疑时，彩色、清晰或有章不能作为影像合格的充分依据；未见嫌疑不等于真实性或持证人核实。属性、标签或清单编号变化后重新按含义选择。
- 脚本保留本体组装、类型与枚举格式校验、来源条目对应及缺失检查，不设业务属性默认表，不自动计算影像合格、账户分类、状态编码或补充证据种类数。
- 规则范围同样采用模型的 rules.keep / rules.drop 显式决定；未明确排除的规则保留。避免属性改名或缺少历史映射导致规则被自动过滤。
- 保留用户此前指定的四个请求标识自动传入。材料提取阶段的请求预填、清单事实整理及原件复核流程保留。
- map / skip 仅在同一请求内复用；set 不落盘，每次 build 重新提交，避免沿用旧判断。
