# 材料盘点与直取

按属性含义匹配请求字段、材料和工商，不按旧对象名硬套。

**读取顺序（红线 14）**：按 init/fill 打印的 `NEXT_MATERIAL` 一份一份来——看这一份（图片/PDF 已卸载到工作区就 Read 那个路径；业务场景照片几张同一轮看）→ 同一轮把这一组的 materials 状态和全部 rows 用 `detail.py fill` 交掉 → 再看下一份。上下文里之前看过的图片变成「…is offloaded…」是平台在腾空间，**不是读取失败**；已 fill 的行就是记录，不为它重读。

## 第一步：附件状态（fill 的 materials）

init 已写好“未提供 / 仅URL / URL 失效”（URL 失效的同时进 notes.unreadMaterials，明细 N 条目用 R01）。对 init 列出的每个待填附件字段给状态：

- **可读**：图片块、PDF 文件块能看到内容；依据 = 原件上一个真实栏位的短原文（PDF 加页码）。**标“可读”就必须给出能核对的原文栏位**，没看清不标。
- **不可读**：当前确实只有占位文字、无法查看；依据写具体原因（记 unreadMaterials）。不可读材料不猜正文，不借用申报/执照名称填开户户名。

判断以实际能看到的内容为准（红线 1）：日志里的 `[unknown]` 是 PDF 的展示降级，扫描 PDF 无文字层也可视觉阅读。没有路径的图文不调用 Read/Glob，也不因找不到文件记“未提供”。与本次目标无关的材料注明“与目标无关”，不必精读。

## 第二步：只对“可读”材料取栏位（按 init 打印的待填行逐条取，规则没引用的栏位也取）

**关键栏位先定位，再读取（在看该份材料的同一轮完成）**：

1. **日期先确认标签及其对应值区，空栏也是提取结果。** 营业执照的「成立日期」「营业期限」和页底发证日期分别读取。只有「成立日期」标签对应的值区实际印有可辨日期，B04 才能有值，证据同时抄标签与日期；不得把相邻行、页底或工商 J09 的日期移到 B04，即使几个日期通常相同。标签可见、值区完整清楚但空白 → `null`、R03，写明标签位置及值区空白；没有该栏也用 R03 并说明；裁切、遮挡、模糊而不能确认 → `null`、R06，不说原件空白。B05/B05-1 照取营业期限，J09 保留工商日期，均不能补 B04。依赖 B04 的成立月数等保留缺口，不填 0。
2. **名称先看该栏末尾字形，再抄全名。** 开户户名 D01 只取「账户名称/开户名称」对应值区，不用正文里另一处公司名、执照或工商名称替代。先从末字向前看末尾 2–4 字，再从头逐字抄录；遇到「司/同/可」「限/恨」等易混字，按实际笔画确认。例如「同」外围是冂框、左侧有竖；「司」左侧敞开，不能因为“有限公司”是常见词就读成「司」。末字或其他关键字无法辨清时整条 `null`、R06，写明位置和候选字，不提交猜出的完整户名。无需为此另起一轮读取。
3. **先记缺栏/错字，再判断异常。** 成立日期清楚空白、户名出现明确错字等现象要保留；不能因为彩色、有章、未见涂改就写“各栏齐全”或把同材料伪造嫌疑 B23/D12 记 false。异常尚不能定性时记 `null`、R06，写具体现象，交人工复核；单凭缺栏或错字不判 true，也不自行改变准入结论。


**营业执照颜色观察与复核（B12，提交 fill 前完成）**：

1. **在看营业执照这一轮内完成本流程**（不另起一轮、不为 B12 再 Read）：看本次 `bizlicUrl` 对应的图片，分别观察证件底色、文字和边框、印章、其他图案；先记录各区域实际可见的颜色，再给出布尔值。来源写材料字段和位置，证据写观察结果。观察不到的区域写“无法辨认”，不按证件通常的配色补全，也不借用其他附件的颜色。
2. 证件区域完整可见且只有黑、白、灰，B12 必须为 false，灰色印章也属于灰色；清晰可见其他色相才能为 true，并指出具体位置和实际颜色。材料可读但颜色无法分辨时填 null、R06；明确看清全为黑白灰时直接填 false，不记为未知。RGB 格式、有印章、文字清晰均不是彩色依据。
3. 准备提交 true 时，针对所声称的有色部位**在同一轮里**再看一眼原图（图片仍在当前轮可见，不需要再次 Read）。例如证据写“印章红色”，就回看那枚章，确认实际可见红色；章的形状、印文和登记机关名称不能证明它是红色。复看为灰色且其余区域也只有黑白灰，改为 false；仍无法分辨，改为 null、R06。复核读取原图，不沿用首次描述作为证据；本步骤不调用仅用于工商差异的 `detail.py recheck`，只提交复核后的 fill 行。
4. 颜色、公司章、登记机关章分别判断。灰色登记机关章可使 B27=true，同时 B12=false；有灰色章不能据此确认有鲜章，也不能改变 B13 的公司章口径。颜色判断不证明原件或真实性。

## 第二步半：与工商比对，不一致先回看原件

fill 提交后，脚本把原件识别值与工商返回**逐项比对（12 项）**：营业执照 B01/B03/B06/B04/B05/B07/B08 对工商 J01/J02/J07/J09/J10/J13/J16（即 J34 的七项）；身份证姓名 C02、开户凭证法定代表人 D08 对 J07；开户凭证户名 D01、租赁合同承租方 G02 对 J01；执照注册资本 B10 对 J08（工商没写单位时不比）（后五项只进 conflicts，不进 J34）。**任一侧没有值不比较。**不一致的项以 `RECHECK_ITEM 条目ID|说明|首次识别=…|首次来源=…|工商 Jxx=…` 列出。**名称类三项（B01、D01、G02）与工商一致时也要逐字复核一次**，以 `RECHECK_ITEM 条目ID|名称（逐字复核）|栏位=…` 列出（不给首次值和工商值，见下方“逐字复核”）。对每一项：

1. 回到原件（图片看对应那张，PDF 看“首次来源”里的页码；已被卸载就 Read **这一份**附件一次，多个条目在同一份材料上一起看，不逐条各读一次），**只重看该栏位**，按原文重新识别一次；不因工商值而改写原文，也不沿用首次的值。
2. 放进**下一次 `detail.py fill` 的 `recheck` 字段**一起交（最后一份材料之后还剩的才单独用 `detail.py recheck`），格式：`[条目ID, 二次识别值, "来源｜二次识别时原件栏位原文"]`；仍无法确认就写 `[条目ID, null, "Rxx｜具体原因"]`。
3. 脚本判定：二次与首次相同 → **确认不一致**，保留原件识别值，source 追加复核记录，J34 与 conflicts 标「已二次识别确认」；二次与首次不同、与工商一致 → 首次识别有误，**更正**；二次与首次不同、与工商也不符 → **两次识别不一致**，置 N R06 不取值；**无法确认** → 置 N 不取值。
4. **工商值永远不覆盖原件识别值**：原件上写的是什么就记什么，两者不同就如实进 conflicts，不裁决真假。
5. **每项只复核一次**；没处理的 RECHECK_ITEM 会让 fill 不出 PASS、`combine.py build` 被拒。改了原件或工商侧的条目，之前的复核结论作废，需重新比对。

**逐字复核**（v43：开户许可证户名原文「…有限公同」被识别为「…有限公司」，与工商一致而未复核，名称不一致规则漏命中）：

1. 只看 `栏位=` 指的那一栏，**先从末字向前确认末尾 2–4 字的实际笔画，再从头读全名**，错字/异体字/缺字原样保留。不参照工商值、首次识别值或本页正文里的另一个名称来补字。**把首次名称加上 `/` 不算复核**；必须重新观察字形。同一份原件当前仍可见就直接看，不增加无关读取。
2. 提交 `[条目ID, 逐字读出的名称, "来源｜逐字：杭/州/浮/岛/…/公/同；末字：同；字形：外围冂框左侧有竖，框内有横与口"]`：`逐字：` 后是该名称每个字用 `/` 拆开（缺了脚本拒收），并写末字及实际可见的判别笔画；字形描述必须来自本次原件，不能照抄示例。只写“末字司、与工商一致”不构成字形依据。看不清就交 `[条目ID, null, "R06｜账户名称末字无法辨清司/同，无法确定原文"]`，不为通过门禁猜字。
3. 脚本判定：与首次相同 → **逐字确认一致**，保留；与首次不同 → 疑似错字被按常见写法纠正，置 **N R06** 不取值并写入 conflicts「原件名称疑似有错字，需人工核对」；同一材料的伪造嫌疑条目（B23/D12/G08）若已记 false，脚本改为 N R06。

复核的是“识别准不准”，不是真伪：确认不一致不等于伪造，不据此填伪造嫌疑类条目，也不据此填任何“真实/已核实”属性。**但名称出现错字/异体字（官方凭证、执照上不该有的字形）时，伪造嫌疑条目不能记 false 或写“未见违背常识”**，记 null R06 并写明异常原文，交人工复核（单凭错字不判 true）。
