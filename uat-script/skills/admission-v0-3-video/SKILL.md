# admission-noshell-v0-3 / admission-v0-3-video

# 视频读取与重试

本次提供了视频才执行。`file_path` 用网关消息 `Video attachment saved at "…"` 里的路径原样（不用请求里的 officeVideoUrl，不自己拼路径）；没有这行就记视频不可读并写明“网关未给出视频保存路径”，不调用 ReadVideo。在第 2 轮与 `detail.py init` 同轮发起 ReadVideo，不等定义；不从文件名推断时长。**E 组条目的依据写视频回答的原话和时间点**

## 问法

`question` 逐字用主提示词第二节的“视频固定问法”（5 项 + 总时长与覆盖时段），不改写、不合并、不加问题。问题里**不得出现申报企业名称**，不得问“是否真实/是否虚构/是否 AI 生成/是否与某名称一致”——这样问会诱导视频模型给出整体印象式推测。名称是否一致由你拿第 5 项读到的原文自己比。

## 三项取值

- **一镜到底自入口起拍**（清单 E08）：第0秒在入口/前台、随后连续进入办公区且无剪辑，才 true；明确从工位区起拍或有剪辑/叠化 false；未答起点或连续性则不传。
- **关键场景可辨识**（清单 E09）：单独看工位、电脑、人员，按本次定义要求映射，不看真实性。读取成功且问过，**必须给 true/false**：能辨认 true；模糊到看不清 false；读取失败不传。
- **场所真实/虚构/核实**（清单 E10，及规则里对应的属性）：仅当第 4 项给出**明确的物理造假证据及时间点**才取值。回答含“疑似、可能、很可能、极有可能、倾向、更像、渲染感、AI生成嫌疑、无法判断”等措辞，**一律不传**，在 conflicts 记“视频模型存疑观察：…（未作为已核实）”。招牌与申报名称不符、叠化转场、无人、文件名为哈希、桌面整齐都不能单独推出虚构或“无法核实实体场所”；招牌原文另记 conflicts。没有新增证据不得把未知改成确定。

**提取明细**：5 项回答分别对应 E01–E07（E07 为“招牌/logo 与申报名称是否不符”，只依据 E06 读到的文字），有值写 `<视频字段> 时间点｜回答原话`；读取失败或回答“无法判断/疑似”的项 value 为 null，写 `R05｜…实际次数` 或 `R06｜…`（推测/未单独问）。E08–E10 按上面三项取值。**E05 的 value 只能是 `"true"`、`"false"` 或 null，不写句子**：

- `"true"`：回答指出了第 4 项列出的明确物理证据（屏幕边框/摩尔纹、绿幕边缘、画面里写着「样板间」「示范间」字样的标识），或具体的违背常识/AI生成痕迹，且**有时间点和具体画面**；source 写这个时间点和画面，同时写入 conflicts“视频模型存疑观察：…（未作为已核实）”。
- `"false"`：回答“未见明确证据”；text 写 `<视频字段> 回答原话｜未见明确证据（不等于真实）`。
- null：只有笼统印象（没有具体时间点和画面）或含推测措辞 → `R06｜…`，印象本身只写入 conflicts。

E05 为 true 也**不因此填 E10 及规则里对应的属性**（那一项仍须明确物理造假证据）。每个有值属性必须有独立问答和时间点证据。视频回答是可能有误的观察，不是业务结论。

## 重试：每视频最多两次尝试

- 超时、no evidence、空返回、VIDEO_QUEUE_TIMEOUT（服务排队、未开始分析，与内容无关）均属读取失败，不是“画面不可辨”。先处理其他工作，再用同一完整问题重试一次；不拆短问，不并发重读。
- 首次已完整分析、仅内容“无法判断”时接受不确定，不重读；确有漏答且补问有望取得缺口证据时，可把一次针对性补问计入同一额度。
- 仍失败：unreadMaterials 写视频、实际次数和原因；相关目标列 unresolvedProperties，input 省略，不用 true/false 占位；不能用照片/租赁合同代替视频。
